# 크리스탈 결제와 광고 (지금은 시연 모드)

## 지금 상태

| 기능 | 지금 | 실제로 켜려면 |
|---|---|---|
| 크리스탈 충전 | **시연 결제.** 확인 창만 나오고 **실제 돈은 청구되지 않습니다.** 카드 정보도 받지 않습니다. | 결제대행사(PG) 계약 + 결제를 서버가 확인하는 서버 |
| 보상형 광고 | **시연 화면.** 5초 카운트다운이고 실제 광고가 아닙니다. | 광고 네트워크 승인 + 개인정보 동의 |

설정은 `payments-config.js` 한 곳입니다.

```js
window.PAYMENTS_CONFIG = { mode: 'demo' };   // 'off' | 'demo' | 'live'
window.ADS_CONFIG = { mode: 'demo' };
```

- `demo`: 시연 (기본). 화면에 "시연"이라고 표시됩니다.
- `off`: 충전·광고 버튼이 "준비 중"으로 잠깁니다. **실제 사용자에게 공개하기 전에는 `off`로 두는 것을 권합니다.** 시연 결제로 받은 크리스탈은 진짜 돈과 무관하지만, 사용자가 "결제가 된 줄" 오해할 수 있습니다.
- `live`: 아직 구현되어 있지 않습니다. 켜도 "연동이 필요해요"라고 나올 뿐 아무것도 청구되지 않습니다.

## 왜 지금 코드만으로 실제 결제를 켤 수 없나

1. **결제 계약이 없습니다.** 결제는 PG사(토스페이먼츠, 포트원 등)와 계약해야 하고, 보통 **사업자등록**이 필요합니다. 개인이 판매하는 경우의 조건은 PG사마다 다르니 PG사에 직접 물어보세요.
2. **저장 데이터를 믿을 수 없습니다.** 이 게임은 브라우저에서 계산해서 저장 데이터(`saves/{uid}`)를 사용자가 직접 올립니다. 그래서 개발자 도구로 `crystals` 값을 고쳐서 올리면 **공짜 크리스탈**이 됩니다. 실제 돈이 걸린 재화는 서버만 고칠 수 있는 곳에 있어야 합니다.
3. **결제 성공을 화면이 알려 주면 안 됩니다.** "결제 완료" 신호를 브라우저가 만들면 누구나 흉내 낼 수 있습니다. PG가 서버로 보내는 결제 확인(웹훅)이나, 서버가 PG에 조회한 결과로만 지급해야 합니다.

## 실제 결제를 붙이는 설계 (구현 안 됨)

```
[게임] 충전 상품 선택 → [서버] 주문 생성(orderId, 금액은 서버가 정함)
   → [PG 결제창] 사용자가 결제 → [PG] 서버로 결제 확인(웹훅)
   → [서버] 금액·주문·중복 검증 → wallets/{uid} 에 크리스탈 적립 (서버만 쓰기)
[게임] wallets/{uid} 를 읽기만 함 → 화면에 잔액 표시
```

- **서버**: Firebase Cloud Functions를 쓰는 것이 가장 가깝습니다. 외부(PG)로 요청을 보내려면 Firebase의 **Blaze(종량제) 요금제**가 필요합니다. 무료 한도가 있지만 결제 수단 등록이 필요합니다.
- **지갑**: `wallets/{uid}` 문서를 만들고 보안 규칙에서 클라이언트 쓰기를 막습니다 (`firestore.rules`에 `allow write: if false`를 미리 넣어 두었습니다. 서버(Admin SDK)는 규칙을 우회해서 쓸 수 있습니다).
- **구매도 서버로**: 크리스탈을 쓰는 것(`buyProduct`)도 서버가 잔액을 차감해야 합니다. 지금은 브라우저에서 차감해서 저장 데이터를 고치면 우회됩니다. 실제 결제를 켠다면 크리스탈로 산 것(장비 상자 결과 등)도 서버가 정하고, 저장 데이터의 `crystals`는 참고용으로만 두어야 합니다.
- **주문 중복 방지**: 지금 게임에는 `orders`(주문 번호) 중복 방지가 있지만 이것도 브라우저 안에서만 동작하므로 서버에서 다시 해야 합니다.
- 코드에서는 `payments.js`의 `createPayments`에 `live` 모드를 채우면 됩니다. 게임 쪽은 `{ status: 'paid', orderId }`만 받는 구조입니다. 다만 위 설계대로면 게임이 크리스탈을 직접 올리지 않고, 서버가 올린 잔액을 읽는 쪽으로 바꿔야 합니다.

## 실제 광고를 붙이는 방법 (구현 안 됨)

- 웹 게임용 보상형 광고는 광고 네트워크 승인이 필요합니다 (예: Google의 웹게임 광고 프로그램). 승인 조건(트래픽, 사이트 심사, 도메인)은 네트워크마다 다르니 직접 확인해야 합니다.
- 유럽 등에서는 광고 개인화 **동의 화면**이 필요할 수 있습니다.
- 광고 보상도 서버 확인이 이상적입니다 (광고 네트워크의 서버 확인 기능). 브라우저만으로 하면 "광고를 봤다"는 신호를 흉내 낼 수 있습니다. 다만 광고 보상은 돈이 아닌 레벨업 1회(하루 3번)이라서 위험은 작습니다. 하루 횟수 제한은 기기 시계를 바꾸는 방법은 막아 두었습니다(사이트를 내려 주는 서버의 응답 시각 `Date` 헤더로 오늘을 정하고, 서버 시각을 못 받으면 새 하루로 넘어가지 않음). 하지만 횟수가 저장 데이터(`adLog`)에 들어 있어서, **저장 데이터를 직접 고치는 방법이나 개발자 도구에서 서버 응답을 가로채는 방법은 막지 못합니다.** 진짜로 막으려면 횟수도 서버(Cloud Functions + Firestore)가 세야 합니다.

## 서비스 전에 확인할 것 (법률 조언이 아닙니다)

제가 확인한 법률 자문이 아니라, 알아봐야 할 항목의 목록입니다. 정확한 내용은 관련 기관·전문가에게 확인하세요.

- **게임물 등급분류**: 게임을 공개 서비스하려면 등급 분류 대상인지 확인해야 합니다 (게임물관리위원회, 오픈마켓 자체등급분류 등).
- **확률형 아이템 정보 공개**: 돈으로 사는 확률형 아이템은 확률을 공개해야 합니다. 이 게임의 장비 상자는 확률을 상품 카드와 구매 확인 창에 그대로 표시합니다 (`store.js`의 `odds`). 실제 결제를 켜기 전에 공개 방식이 요건에 맞는지 확인하세요.
- **청약철회(환불)**: 전자상거래법상 디지털 콘텐츠의 청약철회 안내와 환불 정책이 필요합니다.
- **미성년자**: 미성년자 결제 제한·법정대리인 동의 관련 규정을 확인하세요.
- **사업자등록·통신판매업 신고**, 이용약관, 개인정보처리방침.
- **가격 표시**: 세금 포함 총액 표시를 확인하세요.

## 자동 점검에서 다루는 것

- `node tools/test.js`: 크리스탈 잔액, 주문 번호 중복 지급 방지, 상품 구매·확률, 물약 효과·시간, 가방 확장, 광고 하루 3번(날짜 바뀜 포함)을 확인합니다.
- `node tools/ui-check.js`: 충전(취소·시연 결제), 구매 확인, 상자 결과 창, 광고 카운트다운·중간 취소·3번 제한, 다시 열었을 때 유지를 브라우저에서 확인합니다.
- **실제 결제·광고는 점검할 수 없습니다.** 구현되어 있지 않기 때문입니다.
